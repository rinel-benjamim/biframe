## Bundled media binaries

### FFmpeg

- **Package:** `ffmpeg-static` 5.3.0 ([source](https://github.com/eugeneware/ffmpeg-static))
- **Binary:** FFmpeg 6.1.1-essentials_build-www.gyan.dev
- **Build configuration:** static, GPL (`--enable-gpl --enable-version3`), includes libx264
- **Licence:** **GPL-3.0-or-later**
- **FFmpeg source:** <https://ffmpeg.org/releases/ffmpeg-6.1.1.tar.xz>
- **Windows build and corresponding source information:** <https://www.gyan.dev/ffmpeg/builds/>
- **FFmpeg project:** <https://ffmpeg.org/>

Biframe invokes FFmpeg as a separate executable; it does not link FFmpeg into the Electron application. The packaged application still redistributes a GPL-licensed binary. Redistributors are responsible for providing the corresponding source and the GPL notices for the build they ship. Installing a system FFmpeg instead of the bundled binary does not change the licence of the application source, but it does change what that distributor is shipping.

- **Package:** `ffprobe-static` 3.1.0 ([source](https://github.com/joshwnj/ffprobe-static))

- **Binary:** FFprobe built from the FFmpeg project; the package's own wrapper is MIT. The FFprobe binary itself originates from FFmpeg and may carry the same GPL terms as the build it was taken from. Check the package contents for the exact provenance when redistributing.

## Notes for redistributors

- Keep the licence files included by `electron`, `ffmpeg-static` and `ffprobe-static` inside the packaged application where their terms require it.
- The packaged Windows build contains `resources/app.asar` and `resources/app.asar.unpacked`; the FFmpeg/FFprobe binaries and their notices are in the unpacked tree.
- Do not represent Biframe as distributing FFmpeg under the MIT licence. It does not.
- If you publish a modified Biframe, state the modifications and preserve the MIT notice for the application source.
- For a commercial distribution, review the GPL-3.0 obligations for FFmpeg (including corresponding source) with counsel.
